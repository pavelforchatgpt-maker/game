# Симулятор V1 — сценарная проверка

Модель и результаты предназначены для аудита до написания текстов событий. Канонические правила, геометрия и балансировочные числа не изменяются. Итоговый статус и найденные ограничения: [SIMULATION_REPORT_V1.md](SIMULATION_REPORT_V1.md).

## Запуск

Нужен Node.js 22+; внешние пакеты не используются. Из корня проекта:

```text
node --test simulation/tests/*.test.cjs
node tools/event_slot_validator.cjs
node tools/map_validator.cjs
node simulation/src/run.cjs 128 main
node simulation/src/run.cjs 128 talents
node simulation/src/run.cjs 128 stress
node simulation/src/exact_audit.cjs
node simulation/analysis/travel_math.cjs
```

Основной набор: 90 конфигураций (2, 3, 4 вместе, 4 парами, 4 смешанно × 6 стратегий × 3 режима СТ). Таланты: 15 конфигураций. Стресс-набор: 48 конфигураций. Каждый результат сохраняется сразу; повторный запуск продолжает незавершённый набор. Несовпадение числа наблюдений или отпечатка движка вызывает ошибку вместо смешивания результатов. Для нового движка старые результаты нужно явно перенести в отдельный каталог.

`results/pilot-v0/` — **устаревший диагностический прогон** неполной модели до исправления условий, ограничений способностей и маршрутизации. Не использовать его как оценку вероятности победы.

## Архитектура

`config.json` содержит 88 механических слотов, характеристики героев, кубик, сроки, финальные требования и контрольные суммы источников. `geometry.cjs` использует утверждённые 19 тайлов из `tools/map_data.cjs`, строит реальные графы малых гексов и учитывает открытие 10↔14 в Нереиде.

`kernel.cjs` реализует базовые переходы состояния. `effects.cjs` — предметы и эффекты способностей. `scenario.cjs` — последовательность активаций, движение, выбор целей, события, столицы и финал. `dag.cjs` объединяет одинаковые состояния и вероятностные исходы. `provenance.cjs` запрещает незаметно продолжать расчёт после изменения входных данных.

Для каждого уникального состояния текущего фронтира один раз вычисляются исходы, после чего по ним распределяется вся накопленная группа наблюдений. Путь от первого дня заново не проигрывается. Одинаковые следующие состояния объединяются. Для небольших подзадач используется точное распространение вероятности; для полной партии — выборка ветвей из уникальных состояний. Это не доказательство оптимальности решения всей игры.

Ключ включает все поля механического состояния и внутреннее состояние стратегии, кроме накопительных метрик. Порядок групп сохранён: текущая стратегия использует его для выбора следующей активации. Состав неизвестной части колоды хранится без перестановок. Известный низ колоды после «Шёпота Древа» хранится отдельно, с порядком. Лимиты, закреплённые ведущие, бюджет движения, частично выполненная проверка и выбранная карта также входят в ключ.

Кэш переходов ограничен 4000 записями. Счётчик `reexpanded` отдельно показывает повторное вычисление ранее встречавшегося состояния после вытеснения; нельзя выдавать такую реализацию за неограниченную глобальную таблицу транспозиций. `uniqueExpanded`, `merged`, `cacheHits` и `peakFrontier` доступны для каждого прогона.

## Утверждённые правила и допущения разделены

Три режима не являются новыми правилами событий. Это разрешённый пользователем анализ чувствительности отсутствующего слоя из 29 СТ-карт:

| Режим | Стадия I | Стадия II | Стадия III |
|---|---:|---:|---:|
| ST-NEUTRAL | 0 | 0 | 0 |
| ST-MODERATE | 0 | +1 к сложности СТ-карты | +2 |
| ST-HARSH | 0 | +2 | +4 |

Штраф применяется только к помеченным СТ-слотам. Это числовой суррогат, который не охватывает будущие изменения проходов, наград или вариантов действий. Устойчивость между этими тремя режимами не доказывает устойчивость к любому возможному тексту события.

Основной набор не даёт бонусов талантов. В отдельном наборе вероятность применимости +1 к проверке ТИ равна 25%. Не назначаются соответствия конкретных талантов конкретным картам. Этот набор **не моделирует бонусы талантов в столицах и финале**, поэтому не является полной оценкой их влияния на игру. Способность «Общий талант» не получает выдуманного каталога применимости.

Дополнительные явно заданные допущения:

- Пограничные ТИ условно чередуются между двумя территориями. Стресс-варианты относят их к одной либо другой стороне. Это не утверждение принадлежности клеток и не изменение карты.
- После межтайлового перехода герои размещаются на зеркальной клетке прохода. Точное размещение в зоне входа ещё открыто; влияние иной процедуры не доказано.
- Повторные состояния объединяют затронутые будущие дни, без сложения длительностей. Это временная модель неутверждённого накопления.
- Находясь на доступной ТИ в начале движения, герой может её активировать без ухода с клетки. Отдельное правило этого случая в источниках не найдено.
- Стратегия использует видимые служебные направления выходов и предпочитает внешние A-направления. Она не читает клетки или препятствия закрытого тайла для принятия решения.
- Основной финал назначает ведущих по заранее заданному порядку, без подбора по скрытой характеристике. `announcedFinal` отдельно моделирует известные требования финала.
- Тематическая обоснованность обычной помощи считается выполненной; тексты событий ещё не написаны.
- При переполнении инвентаря стратегия передаёт новый предмет доступному союзнику со свободным местом либо отказывается. Не ищет оптимальную замену или обмен.
- «Обещание» используется только для передачи состояний в ограниченной ситуации; остальные возможные последствия не придуманы. «Чувство пути» фиксирует просмотр, но текущая стратегия после него не отменяет переход.

## Стратегии и пределы выводов

`WIN-MAX-HEURISTIC` экономит время исследования и стремится собрать необходимую энергию. Это эвристика, **не решённая оптимальная политика и не MCTS**. `BALANCED HUMAN`, `EXPLORER`, `TRUST-FIRST`, `ENERGY-FIRST`, `IMPERFECT` отличаются приоритетами ТИ и выбором открытых вариантов наград.

При разделении пары идут от старта в разные стороны; открытые столицы распределяются между ними, чтобы не ждать ведущего чужой пары. В смешанном варианте разделение разрешается с шестого дня. Состав пар фиксирован. Произвольное перераспределение героев, оптимизация всех маршрутов и всех вариантов порядка героев не перебираются. Нельзя объявлять лучшую найденную стратегию доминирующей во всей игре.

Способности выдаются по правилу «случайные три, выбрать одну, остальные не возвращать». Выбор использует объявленный в коде приоритет, без знания будущих карт. Сценарии фиксированных сильных/слабых наборов — отдельные проверки чувствительности, а не обычная процедура выдачи.

## Статистика

`win95` — интервал Уилсона для доли побед **при заданной модели и стратегии**. При 0 побед из 128 верхняя граница около 2,91%, а не доказанный ноль. ESS равен числу равновесных наблюдений; число уникальных узлов DAG не подменяет размер выборки. Для накопительных метрик после объединения путей сохраняются взвешенные средние, но не интервалы разброса отдельных историй.

Отдельные результаты `exact_subsystems.json` относятся к финалу при уже выполненных предпосылках и к одной вытянутой карте, а `exact_travel.json` — к изолированному движению к общей цели. Их нельзя называть вероятностью победы полной партии.

`terminalSummary` разделяет недостабилизированные столицы, нехватку энергии, недостигнутое/неподготовленное Древо и провал финальных проверок. Диагностическая граница `provenCapitalBudgetDead` использует только число оставшихся столиц и максимально доступные активации; она является достаточным, но далеко не необходимым признаком невозможности успеть.

Нулевое число побед, отсутствие применения предмета или способности и недостижение финала в этих стратегиях не доказывают соответствующий дефект правил. Сначала проверяется ограничение движка и стратегии, затем формулируется гипотеза для плейтеста.
