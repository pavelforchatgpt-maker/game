
## Что говорит диагностика причин

В контрольной подвыборке 64 партий выдача всего Trust заранее сокращает средний срок завершившихся у пары примерно с 40.8 до 31.9 дня; бесплатная финальная энергия — до 37.2. Для четверых вместе бесплатная энергия сокращает срок с 37.1 до 29.5, Trust — до 33.3. Для фиксированных пар каждый из этих двух ресурсов улучшает срок примерно с 26.7 до 21.5. Это показывает несколько взаимодействующих ограничений, а не единственный недостаток энергии.

Отключение состояний не устраняет дефицит времени одной группы. Для двух пар улучшение заметнее, но меньше снятия ресурсных требований. Нельзя делать вывод, что состояния «помогают» паре из небольшого изменения условного среднего: изменяются маршруты и набор завершившихся партий.

Узкое место одной группы остаётся даже при благоприятных командных кубиках. Две пары существенно эффективнее используют мировые сутки, но каждая пара хуже проходит командные проверки. Их преимущество в favorable/expected нельзя переносить на ordinary без учёта этих повторных попыток.

## Матрица доказательств и незакрытых требований

| Требование | Статус результата |
|---|---|
| Успешные журналы 2/3/4 | Есть, 16/17/14; структурно проверены, допущения указаны |
| Строгие нижние границы | Есть в релаксации: 10/10/6; разрыв с witnesses не закрыт |
| Exact oracle, абсолютный минимум полной игры | НЕ установлен; favorable policy не выдаётся за oracle |
| Минимум ТИ только для финальной энергии | 4/6/8; достигнут в witnesses без расхода энергии |
| Оптимум Trust/маршрута | Необходимая Pareto-граница и 30 вариантов; глобальная оптимальность не доказана |
| Expected movement | Настоящий случайный кубик, оценка policy; не строгий оптимум |
| Dynamic split | Операции и выбор по состоянию реализованы; все тайминги не перебраны |
| Сравнение | Основные 256–512, отдельная серия 1024; ошибки V1 отделены |
| TIME BUDGET | Мировые сутки, успешные и проигрышные сценарии; указана атрибуция |
| Reasonable-human | Определён и измерен proxy с готовым планом; реальные люди не наблюдались |
| Структурная невозможность до 20 | Опровергнута для сценарной модели; обычный здоровый коридор не доказан |

Этот документ не закрывает точную оптимизацию одним новым win rate. Чтобы окончательно отделить структурное ограничение от недостатка policy, требуется закрыть разрыв нижней/верхней границ полным поиском либо получить независимые результаты сильных игроков. Сейчас надёжно установлены достижимость в модели, влияние размера группы и конкретные ограничения инструмента. Необходимость менять правила из этих данных не следует.

## Воспроизводимость и артефакты

- [bounds.cjs](v2/bounds.cjs), [bounds.json](v2/bounds.json) — BFS релаксации и ресурсная граница.
- [geometry_bound.cjs](v2/geometry_bound.cjs) — отдельная оптимистическая геометрическая граница.
- [route.cjs](v2/route.cjs), [build.cjs](v2/build.cjs), engine.cjs, legacy.cjs — planner и инструментирование; правила проекта не редактировались.
- [experiment.cjs](v2/experiment.cjs) — ветви, trace, мировые дни, диагностический horizon.
- [suite.cjs](v2/suite.cjs) — основные серии с fingerprint. Исторические checkpoints относятся к записанной версии. После изменения кода не обходить проверку fingerprint ради продолжения.
- [supplement.cjs](v2/supplement.cjs) — search, budget, sensitivity, counterfactual, legacy-repaired. [extend.cjs](v2/extend.cjs) — серия 1024. Новые диагностические флаги по умолчанию выключены.
- [facts.cjs](v2/facts.cjs), [validate.cjs](v2/validate.cjs), [validation.json](v2/validation.json) — отдельные проверки.
- [Журнал 2](v2/journal-2.md), [журнал 3](v2/journal-3.md), [журнал 4](v2/journal-4.md); машиночитаемые successful-2/3/4.json.
- Исходные строки всех серий: simulation/v2/runs/. Прежние results.json/comparison.json — архив промежуточного этапа, не итоговые данные.

Команды проверки:

    node simulation/v2/bounds.cjs
    node simulation/v2/facts.cjs
    node simulation/v2/validate.cjs simulation/v2/successful-2.json simulation/v2/successful-3.json simulation/v2/successful-4.json
    node simulation/v2/render_report.cjs

Суммы дневного бюджета проверены: каждый день успешных журналов даёт ровно 1, а не сумму активаций двух групп. Валидатор не доказывает полноту модели всех опциональных эффектов.

Контроль после завершения прогонов: 35 существующих тестов kernel/effects прошли; синтаксис всех V2-модулей проверен; sourceDrift() вернул пустой список. Канонические источники, из которых сформирован config.json, не изменились. Проверены оба набора из трёх успешных журналов, включая строгую проверку дистанции 0 до выхода для conservative. Текущие хеши исходников аудита сохранены в manifest.json; исторические серии сохраняют собственные fingerprints.

Расширенная fixed/team-perfect серия: 366/1024 побед, Wilson95 32.87–38.73%, средний диагностический день 21.89. Накопленная доля изменилась с 37.50% при 512 до 35.74% при 1024; отдельные короткие блоки всё ещё колеблются. Поэтому «стабильность» означает указанную статистическую точность суммарной оценки, а не отсутствие случайных колебаний каждого блока.
