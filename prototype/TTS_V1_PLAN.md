# TABLETOP SIMULATOR — ПЕРВЫЙ ИГРАБЕЛЬНЫЙ ПРОТОТИП / DIGITAL FIRST

**Решение автора от 2026-11-12.** Следующая версия игры создаётся и проверяется **в Tabletop Simulator (TTS) через Steam**. После серии партий с реальными людьми правила, темп, интерфейс и баланс корректируются. **Физическая печать и изготовление тиража — только после цифровых тестов**, не текущий этап.

## Цель первого результата

Получить полностью проходимую кооперативную партию на виртуальном столе, **2–4 игрока, без ведущего**, сохраняя уже утверждённые правила, сюжет и размеры компонентов. Декорации могут быть временными, но игровые компоненты должны иметь достаточно читаемую графику, чтобы участники могли честно оценить удобство, удовольствие и длительность партии.

TTS — симулятор физических объектов: **карты и тайлы — импортируемые плоские изображения на физических игровых объектах**, жетоны и кубики — объекты стола; 3D-миниатюры для героев и акцентов можно добавлять отдельно. **Не нужно моделировать весь мир как компьютерную 3D-локацию**, это замедлит тесты, не улучшив оценку настольной механики.

## Этапы сборки (без пропуска критически важных элементов)

### 0. Базовая игровая сборка и описание компонентов

- Базовые правила: [RULES.md](../RULES.md), временные настройки теста [PLAYTEST_RULES_V0_1.md](../PLAYTEST_RULES_V0_1.md); решения [DECISIONS.md](../DECISIONS.md).
- **19 больших шестиугольных тайлов** по [индексу](../locations/TILE_INDEX.md), [топологии](../locations/MAP_TOPOLOGY.md), все с 19 малыми клетками; закрыты/открываются по существующим правилам. Никаких искусственно новых дорожных связей.
- Личные планшеты 8 героев, 12 талантов, 20 способностей, 12 уникальных предметов; финал и задачи столиц из действующих файлов.
- Три категории ТИ и событие по **колоде, соответствующей типу активированной ТИ**. Всего 88 слотов: 36 Исследование, 34 Встреча, 18 Испытание. **На сегодняшний момент художественно подготовлены и приняты только 36 сюжетов «Исследования»**; нельзя выдавать две другие колоды за готовые.
- Все жетоны доверия народов, общей энергии Древа, состояния Замедление/Задержка, календарь/стадии нестабильности, кубики двух типов, маркеры героев/групп и маркеры ТИ, 5 столиц, финальная система выравнивания.

### 1. Арт-ассеты и разметка TTS

- **Единый стиль изображения:** [арт-стандарт](../art/ART_STYLE_BIBLE_V1.md).
- **Лицевая карточка:** [финальный стандарт](../events/CARD_FACE_STANDARD_V1.md) и [36 коротких текстов](../events/drafts/EXPLORATION_CARDS_PRINT_V1.md); **без печатных ID**, без отдельного текста успеха, две альтернативы через «ИЛИ», II/III размещены после описания и до действий; таланты справа внизу. **Пропорции 70:110 = 7:11** даже в TTS; значение миллиметров — будущая геометрия реальной карты, **не повод сейчас печатать**. На 2Х иллюстрация ниже, чем на 1Х.
- Создать **векторную/слойную систему** шаблонов и программную сборку PNG лиц карт: художественный арт отдельно; название/история/проверка/награда/провал/стадии/таланты автоматически из данных. Хранить исходные ID **в метаданных проекта/именах файлов**, не на лице.
- **Рубашка «Исследования»** по [арту-брифу](../art/EXPLORATION_CARD_BACK_BRIEF_V1.md), общая для всех 36. Отдельные рубашки Встречи и Испытания — позже, в той же визуальной системе.
- Тайлы: художественная основа и точная игровая сетка — **раздельные слои** для контролируемой стыковки и читабельности; наглядная скрытая/открытая сторона. Миниатюры могут сначала быть простыми фигурками.
- Использовать изображения **RGB PNG/JPG**. Для карт генерировать листы **card sheets** со строго известными columns/rows/count и отдельный файл рубашки; TTS поддерживает импорт Custom Deck через **Objects → Components → Custom → Deck**. См. [официальную документацию](https://kb.tabletopsimulator.com/custom-content/custom-deck/).
- Тайлы импортировать через **Custom Tile** ([официальная документация](https://kb.tabletopsimulator.com/custom-content/custom-tile/)); для специальных фигурок — **Custom Model**, только если существенно для игрового опыта.
- Для игры с друзьями изображения и модели должны быть доступны **всем участникам**, а не только на компьютере автора. Подходящий хостинг — **Steam Cloud**; локальные файлы видит только хост. [Официальная инструкция](https://kb.tabletopsimulator.com/custom-content/asset-importing/).

### 2. Стол и интеракции

- Стол с зонами 2–4 игроков, область для собираемой гекс-карты, три колоды, область сброса, рынок предметов/инвентарь и общий трекер.
- Скрытые тайлы должны быть закрыты одинаковыми рубашками; раскрытие по правилам. **Важно убедиться, что игроки не видят закрытые тайлы через ALT/внутренние подсказки**.
- Манипуляции руками: передвижение по клеткам, тайлы, броски кубиков, взятие карт, установка жетонов, обмен/совместное использование разрешённых ресурсов. В первой итерации игра остаётся **настольной игрой без электронного ведущего**, действия в основном ручные.
- Удобство: сохранение текущей партии и возврат к ней, просмотр увеличенной карты, подсказки с краткой памяткой, разборчивые слова и значения характеристик при нормальном масштабе.
- Возможный **Lua-слой после запуска базовой сборки**: кнопка следующего дня, автоматический показ текущей стадии, удобные счётчики, раздача стартовых героев и сбросы, журнал событий и длительности. **Не автоматизировать всё заранее**, пока не проверено, какие действия игрокам удобно совершать самостоятельно.
- Никаких новых механических правил через скрипт: скрипт выполняет только утверждённые действия, проверяемые игроками.

### 3. Первый полный плейтест

- Начать с **2 игроков**, затем 3, затем 4 — отдельно **четверо вместе** и **две пары 2+2**.
- Каждый раз фиксировать: число игровых суток, фактическое время партии, точку окончания, выполненные столицы, ресурсы, распределение по колодам, число неудач/замедлений/задержек, частоту способностей, спорные формулировки, скучные этапы, ощущение повторяющихся событий и момент, когда игроки догадались разделиться.
- Тестировать реальную читаемость **на экране**, видимость тайлов и понятность карточек без устного объяснения автора.
- После партий корректировать дизайн. **Не менять механики и художественные истории в ходе одной тестовой партии**, чтобы сравнение оставалось интерпретируемым. Экспериментальные стадии +1/+2 нуждаются в балансовой проверке.
- Итог: зафиксировать проблемы, внести изменения в исходники GitHub, собрать TTS v0.2, повторить партию. Только после удовлетворительных тестов — подготовка файлов для типографии.

## Что считать «готово для живого тестирования»

**Не только** карточная колода, а сохранённая **воспроизводимая** TTS-партия: все 19 тайлов и 19 клеток каждого, реальные герои/ресурсы/состояния, подходящие 88 событий (другие две колоды ещё предстоит написать), задачи столиц и финал, не требующий мастера. Карты и правила видны игрокам; загрузка ассетов на стороннем компьютере работает.

Первая техническая проба может быть ограничена **столом, несколькими тайлами, тремя картами и фигурками** только для проверки импорта, масштабирования и загрузки; **это не завершённый игровой прототип**.

## Развёртывание и совместная игра

- Для проверки локально: собрать TTS-стол из Custom Deck и Custom Tile, сделать Save & Load.
- Для удалённых игроков: разместить ассеты на Steam Cloud или надёжном публичном хостинге; проверить на компьютере приглашённого игрока. [Облачный импорт](https://kb.tabletopsimulator.com/custom-content/asset-importing/).
- Для распространения тестовой версии: **Steam Workshop с доступом только друзьям/ограниченным кругом**, не выкладывать публично до решения автора. [Steam Workshop](https://kb.tabletopsimulator.com/custom-content/steam-workshop/).
- Хранить в GitHub скрипты, исходные данные, шаблоны, списки ID, инструкции по сборке, версии. **Сохранение TTS в JSON не содержит самих картинок и моделей** — доступность внешних ассетов обязательна. [Официальный формат импорта модов](https://kb.tabletopsimulator.com/custom-content/importing-mods/).

## Что пока не утверждено

- Полная автоматизация Lua vs ручное разрешение событий: начальная настройка — ручная игра с удобными помощниками.
- Финальные пиксельные разрешения, плотность sheets и типы моделей — после проверки в TTS на разных масштабах.
- Влияние стадийных усложнений II/III на винрейт и фактическую длительность.
- Физическая печать, материалы компонентов, допечатная подготовка, производитель и коммерческий тираж — **только после цифрового плейтеста**.
